Why a 3 / 2 replica split is not Scale-OOD

Most tasks have one tiny instance and five large replicas. The suffixes large_1 through large_5 label separate replicas, not five ordered scale levels. We checked serialized file size as a simple proxy. Only 6 of 179 complete tasks (3.4%) grow monotonically from 1 to 5, and the median ratio between adjacent files is 1.000.

Published split

Scale-OOD

Train on tiny instances and test on large instances of the same tasks. This uses the dataset's explicit small/large boundary.

Optional split

Large-replica holdout 3 / 2

Train on three large replicas and test on two others. This tests transfer to held-out replicas or random seeds. It does not test scale extrapolation.

One exception: segundo2019 has only large_1, large_2, and large_5. An exact 3/2 large-only split therefore covers 179 tasks. To retain all 180, use a documented 2/1 split for this task.

How we chose the 30 test tasks

We used a deterministic search instead of drawing 30 tasks at random. The search balances category, formulation, application field, optimization direction, runtime quartile, model-size quartile, publication era, and problem classes with enough examples to split.

Leakage control: earl2005 and its legacy alias ostrowski2012 stay together in train. The release has 180 directories and 179 independent benchmark identities.

Runtime-based limits

Each instance keeps the same limit in every split. We use broad brackets because the timing data includes current reruns and historical runs from different systems. Treating those measurements as one precise speed benchmark would be misleading.

120s5 to 30s

900s>300s or censored

Maximum: one training rollout or evaluation attempt may run for at most 900 seconds (15 minutes). The manifests also report serial upper bounds for compute planning.

Create another split

The four manifests are defaults. The source tables contain enough information to create a different split. splits/time_limits.csv records the task, instance, scale label, Gurobi runtime source, checker status, and execution limit. data/task_catalog.csv adds problem class, formulation, application, year, and difficulty.

This command creates a deterministic 3/2 split of the five large replicas:

python examples/make_custom_split.py \
  --train-count 3 --test-count 2 \
  --incomplete-policy proportional \
  --output my_large_replica_split.csv

Choose --incomplete-policy skip for an exact 3/2 split over 179 tasks. Choose proportional to retain segundo2019 with the 2/1 exception described above. A fixed hash seed makes the assignment reproducible.

Data and reproducibility

The splits use LeoJiangOR/FrontierOR-Audited-180@a6fe77d0c791. All 1,095 reference solutions pass their checker, and every row keeps the source of its runtime measurement.

Run python scripts/build_splits.py to rebuild the files and python scripts/validate_splits.py to check them. MANIFEST.sha256 contains the generated-file hashes.
